# Frontend — сканер вина

Минималистичный mobile-first интерфейс: камера/галерея → настоящий pipeline →
основная карточка Top-1. При неуверенности показаны до 10 кандидатов распознавания
всего (Top-1 плюс до 9 других). Рекомендации и вымышленные демо-вина удалены.

Карточка получает из PostgreSQL название, винодельню, категорию, цвет, регион,
сорта винограда, описание и дополнительные текстовые атрибуты. Ссылка ведёт на
`https://vino-svoe.ru/wines/<slug>`. Эталонное web-фото передаётся без изменения
формата, поэтому прозрачность сохраняется. «Оценка совпадения: X%» показывает
округлённый `100 * clamp(decision.score ?? candidate.score, 0, 1)`. Это ранговый
score, не калиброванная вероятность правильного ответа; пояснение видно в карточке.
При `decision.accepted=false` показывается предупреждение о неуверенном совпадении.
Название и год нужно сверить с этикеткой даже при высокой оценке.
При этом ниже карточки показаны другие кандидаты из итогового ранжирования backend:
уникальные slug, исходный порядок, до 9 дополнительных карточек с web-фото,
названием, винодельней, цветом/годом, score и прямой ссылкой. На телефоне список
в одну колонку, на широком экране — в две. При уверенном ответе список скрыт.
Список не запускает новые модели и не меняет предикт; отзыв относится к Top-1.
Организаторский `/v1/eval/predict` по-прежнему возвращает один `{"slug":"..."}`.

Нажмите заметную кнопку «Сравнить фото» с миниатюрой и лупой или фото вина: исходный снимок плавно
раскрывается рядом с каталожным, без обрезки этикетки. Повторный клик скрывает
сравнение. Поддерживаются клавиатура и `prefers-reduced-motion`.
Во время поиска заголовок и пояснение меняются по реальному `stage` backend:
предобработка, поиск похожих фото, OCR, геометрическая проверка, объединение,
палитра и год. Этапы не имитируются таймером; быстрые могут пройти между опросами.
Во время распознавания исходное фото показывается крупно, до 420 px по высоте,
целиком без обрезки; на низких экранах размер уменьшается по высоте viewport.

«Угадал» подтверждает карточку; «Не угадал» раскрывает форму названия, года,
города/региона, винодельни и дополнительных сведений. Поля необязательные,
но недостаточные или неоднозначные сведения не сохраняются. Backend находит
slug по E5 и ставит подтверждённое фото в очередь добавления visual embedding.
UI показывает сохранение/добавление в поиск; score текстового выбора отзыва не показывается.
Внутренний режим ввода ссылки в свободном поле остаётся для отладки, без
упоминания этой возможности в форме. Повторный отзыв обновляет ту же задачу.
При наличии кандидатов карточка Top-1 и ссылка показываются всегда, даже для
старых ответов `status=no_results`. Только пустой список даёт экран без вариантов.
Низкая уверенность не сохраняет фото автоматически: нужен добровольный отзыв.
Три декоративных элемента используют предоставленный `bg_element.png`;
позиции и повороты выбираются при открытии страницы, фон не перехватывает клики.

## Запуск

Node.js 22.19+:

```bash
npm ci
NUXT_PIPELINE_URL=http://127.0.0.1:8080 \
NUXT_DINO_URL=http://127.0.0.1:8000 \
npm run dev -- --host 0.0.0.0
```

Или из корня репозитория:

```bash
docker compose -f compose.pipeline.yml up -d --build
```

Фронтенд: http://localhost:3000. Backend Swagger: http://localhost:8080/docs.
ML-сервисы в Compose доступны только внутри Docker-сети.

## Настоящий API

Nitro проксирует запросы в том же origin, CORS на браузерном клиенте не нужен:

- `POST /api/search`, multipart `file` → backend
  `POST /v1/eval/predict?wait=false`, multipart `image`, ответ HTTP 202.
- `GET /api/status/<job_id>` → `GET /image/status?job_id=...`.
- `POST /api/feedback` → `POST /feedback`, JSON с job_id, оценкой и уточнением slug.
- `GET /api/images?uri=/data/web_photos/<file>` → исходное фото из DINO.
  Разрешены только плоские имена JPEG/PNG/WebP внутри web_photos.

Время ожидания клиента — 300 секунд, лимит файла — 10 MiB.
Опрос последовательный, с повтором при временных сетевых ошибках.
Отмена прерывает загрузку/опрос в браузере, но не отменяет уже принятую задачу.

Приватные настройки сервера: `NUXT_PIPELINE_URL`, `NUXT_DINO_URL`.
Публичные: `NUXT_PUBLIC_API_BASE=/api`,
`NUXT_PUBLIC_MAX_BYTES=10485760`,
`NUXT_PUBLIC_POLL_INTERVAL_MS=1000`,
`NUXT_PUBLIC_POLL_TIMEOUT_MS=300000`,
`NUXT_PUBLIC_MAX_POLL_ERRORS=3`.

## Камера и телефон

В HTTPS/localhost открывается встроенная камера с предпочтением заднего
объектива, предпросмотром и кнопкой снимка. Разрешение запрашивается у пользователя.
При отказе можно выбрать фото из галереи. Потоки камеры закрываются при уходе
и закрытии окна.

На обычном HTTP-адресе локальной сети используется файловый выбор
`capture="environment"`; доступ к getUserMedia требует secure context.
На телефоне откройте `http://<IP компьютера>:3000` в той же сети; для встроенной
камеры нужен HTTPS. Разрешите сетевой доступ в firewall самостоятельно.

## Проверки

```bash
npm run typecheck
npm run build
npx playwright install --with-deps chromium
npm run test:e2e
```

Браузерные тесты проверяют desktop/mobile, ошибку файла, отказ камеры
(без изменения разрешений), раскрытие фото, доступность и реальную карточку
из каталога. Смена надписей дополнительно проверяется на контрактной fixture
статусов, без запуска ML. Тест реальной карточки
требует работающих ML-сервисов; это self-match/smoke, не измерение качества
на независимых фотографиях. Во время него не запускайте другой ML-benchmark
на той же маломощной машине.
